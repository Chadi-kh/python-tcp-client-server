
6.1)
La classe RemoteMemory simule un client qui communique avec le serveur mémoire distant via TCP.
Elle permet de manipuler la mémoire distante comme un tableau Python normal.


Méthode request :est la méthode principale ,elle crée une socket TCP,
                 se connecte au serveur avec l’adresse et le port donnés,
                 envoie une commande (PUT, GET, POST, DELETE) puis attend 
                 la réponse du serveur avant de fermer la socket.

Méthode getitem :elle permet d'utiliser la syntaxe mem[i].
                 elle envoie la commande GET seg i.

Méthode setitem :elle permet d'utiliser la syntaxe mem[i]=valeur.
                 elle envoie la commande POST seg i valeur.

Méthode free    :elle permet de supprimer le segment mémoire.
                 elle envoie la commande DELETE seg.

Méthode debug   :elle verifie si debug=True , elle affiche les 
                 messages de debogage.

Méthode enter/exit :D'apres une recherche sur le context manager de Python, 
                    j'ai compris que python appelle automatique une fonction
                    a la fin de lexecution d'une instruction.
                    Par exemple :
                    *Sans context manager: Si on ouvre un fichier avec "f = open("test.txt")"
                                           il faut le fermer manuellement avec "f.close()".
                    *Avec context manager: Il ferme automatiquement le fichier ,
                                           "with open("test.txt") as f: ... "  quand le bloc with se termine.
                                        

Test effectué :

J’ai utilisé :

    with RemoteMemory("localhost", 12345, "toto", 512, debug=True) as mem:
        mem[0] = 42

et j’ai vérifié dans les messages debug que la commande DELETE toto
était automatiquement envoyée à la fin du bloc with.
